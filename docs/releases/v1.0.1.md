# DeskBox 1.0.1

桌面收纳盒 —— 把桌面上的快捷方式和文件拖进面板集中管理，桌面立刻变干净。

本版修复了两个**严重问题**。

## 下载

| 文件 | 说明 |
| --- | --- |
| `DeskBox.exe` | Windows x64 单文件，双击即用 |

**运行要求**：Windows 10 1809+ / Windows 11，需安装 [.NET 8 Desktop Runtime (x64)](https://dotnet.microsoft.com/download/dotnet/8.0)。
普通用户权限即可，**不需要管理员**。

## 修复

### 1. 热键无法录入

在设置窗口里按 `Ctrl+A`、`Ctrl+空格`、`Ctrl+F1` 等组合键时，界面一直停在
"继续按下一个字母 / 数字 / 功能键…"，热键永远保存不了。

原因是判断"是否只按下了修饰键"时用了**有符号**比较。`Key` 底层是 `int`，
按 `A`(44) 时 `44 - 70 = -26`，负数 ≤ 1 成立，于是所有 Key 值 ≤ 121 的按键
（字母、数字、空格、`F1`~`F12`、小键盘、方向键……）都被误判成修饰键，函数直接返回。

```csharp
// 原始（有 bug）
if (val - 70 <= 1 || val - 116 <= 5)

// 修复后
if ((uint)(key - Key.LWin) <= 1 || (uint)(key - Key.LeftShift) <= 5)
```

### 2. 快捷方式全部打不开

报"没有应用程序与此操作的指定文件有关联"。

原因：打开 `.lnk` 依赖 Windows 的文件关联，而 `HKEY_CLASSES_ROOT\lnkfile` 下的
`IsShortcut` 很容易被"去掉快捷方式小箭头"类工具删掉，一旦被删，**所有**快捷方式立刻全部打不开。

现在 DeskBox **自己用 `IShellLinkW` 解析 `.lnk`**，拿到目标程序、参数和工作目录后直接启动目标，
不再依赖文件关联；只有解析失败时才回退到原来的 ShellExecute 路径。

实测：把 `IsShortcut` 删掉、确认系统已无法打开任何 `.lnk` 之后，新版本仍能正常启动快捷方式指向的程序。

## 改进

- `HotkeyService` 用命名常量（`ModAlt` / `ModControl` / `ModShift` / `ModWin`）替换魔法数字，
  新增 `ToNativeModifiers(ModifierKeys)`。
- `HotkeyService.KeyDisplayName` 由反编译的数值分支改写为可读的枚举分支，
  补齐 `PageUp` / `PageDown` / `Home` / `End` 等显示名。
- 源码工程可直接用 .NET 8 SDK 编译、发布为单文件。

## 使用提示

- 把桌面上的快捷方式 / 文件 / 文件夹**拖进面板**即可收纳 —— 原文件会被**移动**到收纳目录，桌面立刻变干净。
- 程序常驻托盘，建议到「设置」里录一个呼出热键（如 `Ctrl+Alt+空格`）。
- 收纳的文件本体在 `%AppData%\DeskBox\Items\`，**不要手动删除或改名**；
  想取回文件请用右键「导出到桌面」。

## 已知问题（环境相关，非本程序缺陷）

若**系统里所有**快捷方式都打不开并提示"没有应用程序与此操作的指定文件有关联"，
那是 Windows 的 `.lnk` 关联被破坏了。DeskBox 自身不受影响（它自己解析 `.lnk`），
但其他程序会受影响。恢复方式（需管理员）：

```powershell
reg add "HKLM\SOFTWARE\Classes\lnkfile" /v IsShortcut /t REG_SZ /d "" /f
reg add "HKCU\Software\Classes\lnkfile" /v IsShortcut /t REG_SZ /d "" /f
```

仓库根目录提供了现成的 `fix-shortcut-association.reg`。
